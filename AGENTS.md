# AGENTS.md

Телеграм-бот `batek-rs-tg`. Один бинарник на Rust: без базы, без Discord, без
Python. Наружу только Telegram Bot API и `yt-dlp` для команд со случайными
видео.

Это правила, а не пожелания. Если правило делает задачу больше, сказать об
этом и сделать работу, не отменяя правило ради скорости. Отчитываться о том,
что произошло на самом деле: проваленный шаг цитируется, пропущенный шаг
называется с причиной. Проверенным не называется то, что не прогонялось.

## Сборка и проверка

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release
```

`yt-dlp` должен быть в `PATH` для живого прогона видео-команд. Тесты его не
требуют.

## Ворота 1. Автотесты на реальном объекте

Моков нет. Тест, который проходит и без проверяемой возможности, не тест.

- реестр мемов читает настоящие `music/`, `fotos/` и `video/`, проверяются
  имена, дубликаты, классификация по расширению;
- транслитерация проверяется таблично на реальных именах файлов: «бомжара»
  находит `bomjara1`, «белые розы» находит русское имя, латиница находит
  кириллицу и наоборот;
- разбор вывода `yt-dlp` проверяется на записанной живой выдаче в
  `tests/fixtures/`; синтетических фикстур нет;
- ключевые слова проверяются на границы слов: «320» срабатывает, «1320» нет;
- пути и имена файлов проверяются на временных каталогах.

Когда компонент недоступен (нет сети, нет токена, нет `yt-dlp`), тест печатает
«НЕ ВЫПОЛНЕНО: причина» и это не успех.

## Ворота 2. Проверка живьём в Telegram

Владелец проходит в своём клиенте: `/start`, `/meme`, `/bomjara`,
`/batekfetch`, `/batek`, упоминание в группе, инлайн-меню, ключевые слова.
Агент интерфейс не подменяет, следы это журнал бота и ответы владельца.

## Ворота 3. Инлайн и клавиатуры

Проверяется, что инлайн отдаёт файлы, а не подсказки; что кнопки видео-команд
нажимает только автор; что пустой кэш честно объясняет, почему результата
нет.

## Ворота 4. Измерения

Метод до и после, иначе пары не сравнимы:

```bash
date +%s && cargo build --release && date +%s
stat -c %s target/release/batek-rs-tg
```

- размер релизного бинарника;
- время холодной и инкрементальной сборки;
- старт до строки «Telegram: бот ... запущен»;
- RSS в покое, без дочернего `yt-dlp`, по `/proc/<pid>/status`.

Записано 2026-11-07: бинарник 6 934 728 байт (`stat -c %s`), холодная сборка
135 с, пересборка после правки 74 с. В контейнере RSS 5 356 КБ (`VmRSS`),
пик 5 468 КБ (`VmHWM`), 30 мемов, содержимое образа 117.6 МБ (`du -shx /`).
Версия `yt-dlp` 2026.10.26, sha256 проверяется при сборке образа.

Регрессия против записанных чисел это дефект, если не названа и не принята.

## Ворота 5. Документация

README и комментарии в коде на русском, без эмодзи, без длинных тире, без
маркетингового тона. Каждое число со ссылкой на команду или измерение.
Комментарий рядом с кодом объясняет, почему решение такое и какое ограничение
оно обслуживает.

## Контракты

- Токен только из `TELEGRAM_TOKEN`, в код и логи не попадает.
- Мемы это файлы из `music/`, `video/` и `fotos/`, имя это имя файла без
  расширения. Файлы не переименовывать без причины.
- Ключевые слова на оба алфавита: у каждого действия в `KEYWORD_REACTIONS`
  должна быть как минимум одна кириллическая фраза и одна ASCII фраза
  (латиница, транслит или чисто цифровая). Докажет тест
  `keywords::tests::every_action_has_cyrillic_and_ascii_phrase`.
- `/triggers` отладочная команда: она не объявлена в списке команд Telegram
  и работает только у пользователя, чей id в `TG_DEBUG_USER_ID`. Без
  переменной или с нечисловым значением команда отвечает, что отладка
  выключена, содержимого не показывает.
- Лимит Telegram на загрузку 50 МБ, проверяется до отправки.
- Базы нет. Правки из бота хранятся в двух JSON-файлах в каталоге
  `<корень>/data/`: `keywords.json` (добавленные фразы и выключенные
  встроенные) и `access.json` (модераторы и одноразовые приглашения).
  Это не база, а два файла настроек: чтение при старте, атомарная запись
  через временный файл и `rename`. Встроенная таблица `KEYWORD_REACTIONS`
  остаётся источником правды, файл только дополняет её и выключает
  отдельные фразы. Новая потребность в данных снова обсуждается до кода.
- `/admin` это команда управления. Она не объявлена в списке команд
  Telegram и открыта только пользователю из `TG_ADMIN_USER_ID`, по тем же
  правилам молчания для чужих, что и `/triggers`. Админ добавляет
  модераторов по числовому id и выдаёт одноразовые приглашения сроком
  15 минут. Модератор правит ключевые слова, но не выдаёт права ни
  модератора, ни админа. Админа из файла назначить нельзя: только
  переменная окружения.
- Загрузка файлов через бота открыта только админу. Bot API отдаёт ботам
  файлы не больше 20 МБ, поэтому большие видео кладутся в `video/` вручную,
  как раньше. Имя файла проверяется: без `/`, `\`, `..` и управляющих
  символов, расширение из списка `MemeKind::from_path`. Запись идёт во
  временный файл рядом с целевым и переименовывается, частично записанный
  файл в каталог не попадает.
- Внешняя зависимость ровно одна: `yt-dlp`. Если его нет, видео-команды
  отвечают отказом, остальное работает.

## Git

- Тема коммита императивом, без точки, не длиннее 72 символов.
- Один коммит это одно изменение, рефакторинг отдельно от поведения.
- Автор из `git config user.name` и `user.email`.
- Атрибуции ИИ и ссылки на сессии в коммиты не попадают.
- Пуш только после явного согласия владельца.

## Ворота 6. Секреты и безопасность

- Токен только из `TELEGRAM_TOKEN`; в коде, логах, ответах и дочерних
  процессах его быть не должно. `yt-dlp` запускается с `env_clear()` и
  получает ровно `PATH`, `HOME`, `LANG`, `TMPDIR`, плюс `--ignore-config`:
  чужой пользовательский конфиг не читается.
- `.env` содержит секрет и должен быть `chmod 600`. Файл не коммитится.
- Ошибка разбора `TG_CACHE_CHAT` логируется без значения: в журнале только
  факт, что это не число.
- Пользовательский текст не возвращается в чат сырым. `/meme` показывает
  метку без управляющих символов и переводов строк, не длиннее 64 символов.
- Каталог мемов читает только обычные файлы: символические ссылки
  пропускаются, чтобы не отдать файл за пределами `music/`, `fotos/`,
  `video/`.
- Контейнер работает без новых привилегий: `no-new-privileges`, `cap_drop:
  ALL`, `pids_limit: 256`, журнал с ротацией. Сеть хоста оставлена осознанно,
  потому что портов у бота нет.
- Контрольная сумма `yt-dlp` в Dockerfile проверяется через `sha256sum -c`;
  скачивание только по HTTPS с `--proto '=https' --tlsv1.2`. Ослаблять
  проверку нельзя без названной причины.

## Ворота 7. Производительность

- Горячие пути не нормализуют таблицы на каждый вызов. Индекс ключевых слов
  строится один раз при старте из встроенной таблицы и файла правок и
  пересобирается только после правки из бота, не на сообщение. Ключи имён
  мемов считаются при `scan`, цели действий для `/triggers` тоже
  предвычислены. Новая фраза добавляется в таблицу, а не в отдельный
  список. Каталог мемов пересобирается после загрузки файла, а не на
  каждый запрос.
- Случайный id YouTube выбирается под одной блокировкой чтения, без копии
  векторов вкладок.
- Кэши ограничены: `/batekfetch` отдаёт снимок 15 секунд, кэш YouTube
  обновляется раз в 12 часов и не ходит в сеть на старте, если файл моложе
  интервала; карта лимитов ключевых слов чистится и не растёт бесконечно.
- Инлайн-ответ не превышает `INLINE_RESULT_LIMIT` даже с подсказкой
  «загружается», id результатов короткие (`m{index}`).
- Релиз собирается с `lto = "thin"` и `codegen-units = 1`. Числа до и после
  записываются в README; регрессия без объяснения считается дефектом.
